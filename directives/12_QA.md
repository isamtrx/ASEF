# DIRECTIVE-12 — QA

## Purpose

Règles de validation qualité. Référence les standards QA pour les gates G3 et G4.

> Règles détaillées : `.github/instructions/qa.instructions.md`

Pourquoi elle existe : garantir que la validation qualité est exécutée réellement,
pas simulée.
Quand elle est utilisée : toute tâche avant livraison.
Quelle décision elle encadre : quand une tâche est prête à être livrée.
Quelle mauvaise action elle empêche : rapport QA sans commandes exécutées.

## Scope

Couvre : G3 (lint), G4 (tests), rapports QA.
Ne couvre pas : sécurité (G5, voir directive 13), release (G7, toujours humaine).

## Mandatory Rules

1. [QA-001] Exécuter `ruff check .` avant tout rapport G3.
   - Why: le lint doit être vert avant merge.
   - Blocks: rapport G3 sans exit code de ruff.
   - Evidence: `ruff check . 2>&1` + exit code.

2. [QA-002] Exécuter `pytest -q` avant tout rapport G4.
   - Why: les tests doivent passer avant merge.
   - Blocks: rapport G4 sans exit code de pytest.
   - Evidence: `pytest -q tests/ 2>&1` + exit code.

3. [QA-003] Un rapport QA doit suivre le format défini dans .github/instructions/qa.instructions.md.
   - Why: standardisation pour parsing automatique.
   - Blocks: rapport sans verdict final.
   - Evidence: rapport avec sections Gate G3, Gate G4, Verdict.

4. [QA-004] Aucun nouveau warning critique sans documentation.
   - Why: les warnings non documentés s'accumulent silencieusement.
   - Blocks: nouveau warning ruff non adressé.
   - Evidence: diff ruff warnings avant/après.

## Required Inputs

- `.github/instructions/qa.instructions.md` — format de rapport
- `pyproject.toml` — config ruff

## Required Outputs

- Rapport QA formaté (Gate G3 + Gate G4 + Verdict)
- Exit codes des commandes exécutées

## Validation Checklist

- [ ] `ruff check .` exécuté → exit code documenté
- [ ] `pytest -q tests/` exécuté → exit code documenté
- [ ] Rapport QA produit avec format standard
- [ ] Verdict final explicite (✓ ou ✗)

## Rejection Criteria

- `ruff check .` → exit non-zéro → BLOCKED_BY_TEST_FAILURE
- `pytest -q` → exit non-zéro → BLOCKED_BY_TEST_FAILURE
- Rapport sans exit codes → REJECTED (auto-certification)
